<Concepto>
Ya trabajaste con las tres herramientas de la ruta: Excel, SQL y Python con pandas. No compiten entre sí: cada una es la más cómoda para un tipo de trabajo, y en un equipo de datos real se usan juntas.

**Excel: explorar y compartir.** Para mirar un archivo por primera vez, hacer un cálculo puntual o entregar un reporte a alguien que no programa, una planilla es lo más rápido. Se complica cuando el archivo crece a cientos de miles de filas, cuando varias personas editan a la vez o cuando hay que repetir los mismos pasos a mano cada semana.

**SQL: preguntarle a una base de datos.** Cuando los datos viven en una base de datos (el sistema de ventas, el ERP, la plataforma web), SQL trae exactamente lo que necesitas, filtrado y resumido, sin descargar todo. Funciona igual con mil filas que con cien millones.

**Python y pandas: procesos con muchos pasos.** Cuando el análisis combina fuentes distintas (una consulta, un CSV, una planilla de otro equipo), tiene muchos pasos de limpieza o hay que repetirlo, un script de Python lo deja escrito de punta a punta. La próxima vez solo lo vuelves a correr, y cualquiera puede revisar qué se hizo.

**Lo mismo en las tres.** El total vendido por región se escribe así en cada herramienta:

```text
Excel:   =SUMAR.SI(C:C; "norte"; G:G)     (una fórmula por región, o una tabla dinámica)
SQL:     SELECT region, SUM(monto) FROM ventas GROUP BY region;
pandas:  ventas.groupby("region")["monto"].sum()
```

**Juntas en el trabajo real.** Un flujo común: SQL trae los datos de la base, pandas los limpia y los cruza con otras fuentes, y el resultado se exporta a un CSV o a una planilla para quien lo necesita, o alimenta un tablero de Power BI.
</Concepto>

<Debrief>
Excel para lo puntual y para compartir, SQL para traer datos desde una base y Python con pandas para procesos de muchos pasos que se repiten. La mejor herramienta depende de dónde están los datos y de cuántas veces vas a repetir el trabajo.
</Debrief>
