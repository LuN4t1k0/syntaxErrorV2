<Concepto>
Excel es la herramienta de datos más usada del mundo, y por buenas razones. Pero tiene límites, y saber dónde están te dice cuándo conviene pasar a otra herramienta, como la base de datos y SQL que vienen en el siguiente tramo de la ruta.

**Cuando Excel alcanza.** Tablas de cientos o algunos miles de filas, análisis puntuales, presupuestos, reportes que una persona arma y comparte. Es rápido de empezar, todos lo saben abrir y ves los datos mientras trabajas.

**Sus límites.**
- **Tamaño:** una hoja admite poco más de un millón de filas, y mucho antes de eso se pone lenta.
- **Varias personas a la vez:** si dos personas editan copias distintas del mismo archivo, aparecen versiones como "ventas_final_v3_REVISADO.xlsx" y nadie sabe cuál es la buena.
- **Reglas:** nada impide escribir texto en una columna de montos o borrar una fila por error.
- **Historial:** es difícil saber quién cambió qué y cuándo.

**Qué aporta una base de datos.** Guarda millones de filas, permite que muchas personas y sistemas lean y escriban al mismo tiempo, exige reglas (un monto tiene que ser número, cada pedido tiene que apuntar a un cliente que existe) y se consulta con SQL, que trae exactamente lo que pides.

**No son excluyentes.** Lo habitual es que los datos vivan en una base de datos y que una consulta SQL los traiga para analizarlos o presentarlos en Excel o Power BI. En la ruta vas a usar las tres herramientas, cada una donde mejor funciona.
</Concepto>

<Debrief>
Excel para análisis puntuales y tablas manejables; una base de datos cuando crecen el volumen, la cantidad de personas o la necesidad de reglas. En el trabajo real se combinan: SQL trae los datos y Excel o Power BI los presentan.
</Debrief>
