<Concepto>
Algunas preguntas son de sí o no: "¿este estudiante tiene alguna inscripción en observación?", "¿este curso tiene inscritos?". `EXISTS` responde eso para cada fila: es verdadero si la subconsulta devuelve al menos una fila.

<Sintaxis lenguaje="sql" codigo={"SELECT columnas\nFROM tabla_a AS a\nWHERE EXISTS (\n  SELECT 1 FROM tabla_b AS b WHERE b.a_id = a.id\n);"} />

**Una subconsulta que mira la fila de afuera.** Dentro del `EXISTS`, la condición `i.estudiante_id = e.id` usa la fila de `estudiantes` que se está revisando. Por eso la subconsulta se evalúa una vez por cada estudiante. A esto se le llama subconsulta correlacionada.

<SqlEjemplo consulta={"SELECT e.nombre\nFROM estudiantes AS e\nWHERE EXISTS (\n  SELECT 1 FROM inscripciones AS i\n  WHERE i.estudiante_id = e.id AND i.estado = 'observacion'\n);"} />

**No importa qué devuelve.** `EXISTS` solo pregunta si hay alguna fila. Por eso se escribe `SELECT 1`: el valor da igual.

**NOT EXISTS: los que no tienen.** Es la forma más clara de encontrar lo que falta: estudiantes sin inscripciones, cursos sin inscritos, clientes sin compras.

<SqlEjemplo consulta={"SELECT e.nombre\nFROM estudiantes AS e\nWHERE NOT EXISTS (\n  SELECT 1 FROM inscripciones AS i WHERE i.estudiante_id = e.id\n);"} />

**Frente a un JOIN.** Un `JOIN` repite al estudiante una vez por cada inscripción que cumple; `EXISTS` lo muestra una sola vez, porque solo pregunta si existe.
</Concepto>

<Debrief>
```sql
SELECT c.titulo
FROM cursos AS c
WHERE NOT EXISTS (
  SELECT 1 FROM inscripciones AS i
  WHERE i.curso_id = c.id AND i.estado = 'riesgo'
);
```

Cinco cursos, incluido Python para análisis, que no tiene inscritos y por lo tanto tampoco riesgo. El intento con `JOIN ... WHERE estado <> 'riesgo'` responde otra pregunta: lista cursos con alguna inscripción que no está en riesgo, aunque tengan otras que sí.
</Debrief>
